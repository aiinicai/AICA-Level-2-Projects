Write a complete, single-file Python desktop application named `bankdoc_processor.py` ("BankDoc Processor & Renamer v1.0") designed as an offline utility for an Indian Chartered Accountant (CA) office. Provide the full, uninterrupted Python code without placeholders or omissions.

### 1. TECH STACK & DEPENDENCIES
- Python 3.9+ using `customtkinter`, `tkinter` (`ttk`), `pymupdf` (`fitz`), `pillow` (`PIL`), `openpyxl`, and `reportlab`.
- Include a startup dependency check that catches missing libraries and shows a friendly message (both in console and a Tkinter messagebox) with the exact `pip install customtkinter pymupdf pillow openpyxl reportlab` command before exiting.
- Use a background `TaskRunner` (thread + `queue.Queue` polled via `.after(80, ...)`) so the GUI never freezes during folder scans, LLM requests, exports, backups, or batch renaming.

### 2. STRICT OFFLINE & PRIVACY DESIGN
- **Loopback-Only Network Guard:** Strictly validate all LLM server URLs so only `127.0.0.1` or `localhost` are permitted (`LoopbackViolation` raised otherwise). Rebuild URLs from validated parts, disable system proxies (`urllib.request.ProxyHandler({})`), and block all HTTP redirects.
- **In-Memory PDF Unlocking (`DecryptedCache`):** Password-protected PDFs must be unlocked in memory only (`doc.tobytes(encryption=fitz.PDF_ENCRYPT_NONE)`), keyed by file path, size, and `mtime_ns`. Never write passwords to disk, logs, JSON, or Excel, and immediately clear password variables after use. Include a sidebar button to clear unlocked PDF copies from memory.
- **Zero Hallucination Cross-Check:** For text-layer PDFs, cross-check extracted dates, amounts, transaction IDs, payer, payee, and remarks against the PDF's actual text. Flag any unverified or conflicting values for manual review.

### 6. AI PROMPTING & EXTRACTION RULES (CRITICAL FOR JPG/IMAGES)
- Extract payload from PDFs using direct text if `>= 40` non-whitespace characters exist (up to 6 pages); otherwise render up to 3 pages as PNG base64 images for vision models. For image files, apply EXIF transpose and convert to PNG base64.
- Ask the LLM to return a single JSON object with: `is_bank_transfer_receipt`, `transaction_id`, `date_candidates`, `amount_candidates`, `payee_name`, `payer_name`, `remarks`, `mode` (`NEFT`, `RTGS`, `IMPS`, `UPI`, `OTHER`).
- **Prevent Payer/Payee Confusion on JPGs & Screenshots:**
  - Explicitly instruct the LLM in `SYSTEM_PROMPT` and `USER_PROMPT` how to distinguish `payee_name` (Receiver / Beneficiary / "Paid to" / "To" / "Credited to" — typically prominent at the top of Indian UPI/bank app screenshots like GPay, PhonePe, Paytm, HDFC, ICICI, SBI, Axis) from `payer_name` (Sender / Remitter / "From" / "Debited from" / "Paid by").
  - Instruct the LLM that if a screenshot only shows `"Paid to [Name]"` and shows only a bank name + masked account number under `"Debited from"` without the sender's personal/company name, `payer_name` MUST be `null` — never copy `payee_name` into `payer_name`, and never put a bank name, branch, IFSC, or account number in either field.
  - In `apply_llm_result`, if `payer` looks like a bank/account label, clear it; if `payer` and `payee` are identical on an image file, automatically clear `payer` and add a warning note.
- **Indian Date & Amount Formatting:**
  - Parse numeric dates using the Indian convention `DD/MM/YYYY` (plus `DD-MMM-YYYY`, `YYYY-MM-DD`, etc.) and store internally as ISO `YYYY-MM-DD`, displayed as `DD-MMM-YYYY`.
  - Canonicalize amounts: whole numbers format as `"Rs.1000"` (strip `.00`), while decimals format as `"Rs.1000.25"`.
