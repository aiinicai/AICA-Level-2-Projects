PROMPT 2 - SIMPLIFY THE APPLICATION AROUND THE CLIENT AND PROJECT
================================================================
The dashboard is too complex. Redesign it around the active client and active project rather than showing the complete dataset together. Once a project is created, imports, GSTINs, verification results, evidence and reports must remain separate for that project.

The user may not have an authorised GSP or API provider. Keep the authorised API architecture available for future use, but do not make provider credentials compulsory. Portal-assisted verification must work without configuring a GSP.


PROMPT 3 - COMPLETE THE PORTAL WORKFLOW WITH MANUAL CAPTCHA
==========================================================
After starting verification, the application must automatically enter the selected GSTIN in the GST Portal search field. If client login details have been saved, it may fill the login ID and password automatically, but CAPTCHA, OTP or MFA must remain manual.

Whenever CAPTCHA is required, clearly tell the user to enter it. After the portal accepts CAPTCHA, the remaining work should continue automatically: read the taxpayer details, open the filing table, select the required financial year, capture the filing data, save the evidence PDF and proceed to the next GSTIN.

Do not bypass or automatically solve CAPTCHA and do not use undocumented GST Portal APIs.


PROMPT 4 - INTERRUPTION, RETRY AND CLEAR ERROR MESSAGES
======================================================
If verification is interrupted, Retry and Resume must start working again immediately instead of leaving the GSTIN permanently pending. Add reliable Pause, Resume, Skip, Retry Selected Now and Reset Project Queue controls.

Do not delete completed verifications when resetting or recovering a queue. Error messages should be understandable to a normal user and should distinguish portal downtime, session expiry, redirect problems, CAPTCHA failure, timeout, missing data and browser errors. Technical details may be written to the application log.


PROMPT 5 - STOP AFTER THE FINAL GSTIN AND USE THE SELECTED FINANCIAL YEAR
============================================================================
The process must stop cleanly when the last pending GSTIN is completed. It must not repeat or save the final GSTIN again.

The evidence PDF and captured filing data must relate to the financial year selected in the project, not merely the latest year displayed by the portal. Map labels such as “FY 2025-26” to the portal label “2025-2026”. If the selected financial year or the required filing table is not available, show a clear error and retain the GSTIN for retry instead of saving an incorrect verification.

Provide financial years from FY 2017-18 through the ongoing financial year.


PROMPT 6 - CAPTURE BOTH RETURN TABLES AND INFER FILING FREQUENCY
================================================================
Capture the filing details displayed for both GSTR-3B and GSTR-1/IFF for the selected financial year.

The portal filing list may not expressly show whether the taxpayer was monthly or quarterly. Infer the pattern from the displayed tax periods. If consecutive months are shown, treat those periods as monthly. If the next filed period appears after a three-month gap and the displayed periods are quarter ends, treat that quarter as quarterly. Where the pattern changes during the year, store the frequency period-wise instead of assigning one frequency to the entire year.

Clearly label this result as inferred from the filing-period sequence.


PROMPT 7 - GENERAL DUE DATES AND DELAY DAYS
===========================================
The report should show expected due dates and delay in days for GSTR-1/IFF and GSTR-3B. Where the GST Portal does not supply a due date, calculate a clearly labelled general statutory due date based on return type, tax period and inferred filing frequency.

Do not present the generic due date as final where a notification, extension, state category or taxpayer-specific fact may change it. Add a professional caution that applicable extensions must be checked separately.


PROMPT 8 - PERIOD-AWARE GSTR-2A/2B IMPORT AND INVALID GSTIN REPORTING
====================================================================
When importing GSTR-2A/2B or invoice data, allow the user to choose the relevant financial year and either Annual or a specific month. The latest import period should automatically link to the verification search period, while still allowing manual correction.

Annual imports should aggregate all invoice values GSTIN-wise. Monthly imports should also consolidate across the project for annual reporting, but the user must be able to export a selected month with its GSTIN list and amounts.

Do not report workbook headings, labels or instructions as invalid GSTINs. If a genuine invalid GSTIN-like value is found, identify the exact source file, sheet and row so that the user can correct it.


PROMPT 9 - PRESERVE THE CORE FUNCTION WHILE ADDING REPORTING
============================================================
Keep the main GSTIN verification workflow stable while adding project-wise and period-wise reporting. The Excel export should contain a supplier summary, invoice details, GSTR-1/IFF and GSTR-3B filing rows, exceptions, evidence index and import log. It should preserve GSTIN-wise consolidated totals while also providing period-wise GSTIN totals.

The application must never conclude that filing GSTR-3B proves invoice-wise payment of tax or the recipient’s eligibility for input tax credit.


PROMPT 10 - FINAL BUILD, TESTING AND DEPLOYMENT
===============================================
Prepare the final production version as Python source, a standalone Windows executable and an installer that runs on Windows 10 and Windows 11 without requiring Python.

Test at least the following critical behaviours:

1. GSTIN normalisation, checksum validation and invalid-GSTIN exclusion.
2. Duplicate GSTINs across many invoices and multiple imports.
3. GSTIN-wise aggregation while preserving invoice-level data.
4. Strict separation between client projects.
5. Correct financial-year mapping and filing-row capture.
6. Monthly, quarterly and changed-frequency inference.
7. Due-date and delay calculation.
8. Evidence-PDF fallback and short filenames.
9. Queue recovery and stopping after the final GSTIN.
10. Excel exports, backup and safe database migration.

Do not package any real client database, passwords, GST Portal sessions or confidential evidence in the final submission.
