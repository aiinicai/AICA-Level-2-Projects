Below is the complete Codex prompt incorporating GSTIN deduplication, invoice-wise aggregation, GSTR-2A upload, shorter PDF filenames, browser-assisted CAPTCHA verification, Excel/PDF reporting, and EXE deployment.

Act as a senior Python application developer and build a complete, production-ready Windows desktop application named:

ASG GST Supplier Verifier

The application is intended for Chartered Accountants handling GST scrutiny, ITC verification, supplier compliance checking, and GST litigation.

The application must verify supplier GST registration status and GSTR-3B filing status for a selected financial year using data imported from GSTR-2A, Excel, PDF, pasted GSTINs, or manually entered GSTINs.

The final application must run:

1. Through Python source code.
2. As a standalone Windows EXE without requiring Python installation.
3. Through a Windows installer created using PyInstaller and Inno Setup.
4. Offline except when connecting to the official GST Portal or an authorised GST API provider.

Use the following technology:

* Python 3.12 or compatible stable version
* PySide6 for the desktop interface
* SQLite for the local database
* pandas and openpyxl for Excel handling
* PyMuPDF for PDF extraction and generation
* ReportLab where required for formatted reports
* Playwright with Microsoft Edge for GST Portal browser automation
* pytesseract only as an optional OCR fallback for scanned PDFs
* cryptography or Windows Credential Manager for secure storage of API credentials
* PyInstaller for EXE packaging

Do not use Tkinter.

## 3. Mandatory GSTIN Deduplication

The application must never verify the same GSTIN repeatedly within the same project.

Example:

If one GSTIN appears in 100 invoices, it must:

* Appear only once in the verification queue.
* Be searched on the GST Portal only once.
* Have all invoice values aggregated under that GSTIN.
* Show the invoice count as 100.
* Show GSTIN-wise total taxable value.
* Show GSTIN-wise total IGST.
* Show GSTIN-wise total CGST.
* Show GSTIN-wise total SGST.
* Show GSTIN-wise total Cess.
* Show GSTIN-wise total GST.
* Show GSTIN-wise total invoice value.
* Show GSTIN-wise total notice amount, where provided.

Keep the original invoice-level data separately for reconciliation and evidence.

Use GSTIN as the unique key after:

* Removing spaces
* Converting to uppercase
* Removing invalid symbols
* Validating the 15-character GSTIN format

Where the same GSTIN appears in multiple uploaded files, merge and aggregate it instead of creating duplicate records.

## 4. GSTIN Validation

Before portal verification, validate:

* Exactly 15 characters
* First two characters are numeric
* PAN portion follows the GSTIN format
* Fourteenth character is Z
* GSTIN checksum, where practical
* Duplicate GSTIN
* Blank GSTIN
* Invalid characters

Invalid GSTINs must be shown separately and excluded from the portal search queue.

## 7. Monthly and Quarterly Filing Logic

The application must correctly distinguish monthly and quarterly GSTR-3B filing.

For a monthly filer, expected periods are:

* April
* May
* June
* July
* August
* September
* October
* November
* December
* January
* February
* March

For a quarterly filer, expected periods are:

* April-June
* July-September
* October-December
* January-March

Do not mark April and May as not filed separately where the supplier was filing quarterly for April-June.

Where filing frequency changed during the year, store the frequency period-wise.

Example:

* April-June: Quarterly
* July-March: Monthly

Create a filing expectation engine that determines the correct applicable GSTR-3B period.
