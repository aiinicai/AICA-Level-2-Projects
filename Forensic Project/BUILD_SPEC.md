# BUILD SPEC — Red Flag Engine

**A forensic accounting fraud-risk engine for Indian statutory and internal audit.**

You are building a complete, runnable Python application from this specification. Everything you need is in this file. Do not ask clarifying questions — where this spec is silent, choose the simplest option that satisfies the acceptance criteria at the end.

---

## 0. THE ONE-PARAGRAPH BRIEF

Build a local Streamlit web app. The auditor uploads **three or more years of a company's trial balance** (Excel or PDF only). The app parses it, derives a balance sheet, profit & loss and indirect cash flow, then runs **44 deterministic fraud-risk rules** and **4 published forensic models** over the data. It scores the result, buckets it red / yellow / green, and produces a ranked "where to audit deeper" report plus an Excel working paper and a client evidence-requisition list. It never concludes that fraud occurred — it establishes *predication*, the professional term for a reasonable basis to investigate further.

The rule library is derived from the ICAI (Institute of Chartered Accountants of India) Board of Studies study material on Forensic Accounting, Chapters 3, 4 and 6.

---

## 1. HARD CONSTRAINTS

Read these first. Violating any of them is a build failure.

1. **Input is strictly `.xlsx`, `.xls` and `.pdf`.** No CSV, no JSON, no XML upload paths.
2. **The app refuses to score fewer than 3 financial years.** The Run button is disabled and the reason is stated on screen.
3. **Rules live in YAML, not Python.** Thresholds must be editable by a non-programmer without touching code.
4. **Never write the words "fraud detected", "fraudulent", or "guilty" in any output.** Use "flagged", "exception", "requires further examination".
5. **Do not implement the 13 methods marked `not_implemented`** in section 8. Declare them in the registry; do not write stubs, dead code, or placeholder functions for them.
6. **No network calls at runtime.** Client financial data must never leave the machine.
7. **The original uploaded file is never modified.** Hash on arrival, work on a copy in memory.
8. **Every number shown in the UI must be traceable** to a ledger row or a stated formula. No magic constants outside `config/`.

## 4. CANONICAL DATA SCHEMA

Everything normalises into these three DataFrames. All downstream code reads only these — never the raw upload.

### 4.1 `ledgers` (long format — one row per ledger per financial year)

| column | type | notes |
|---|---|---|
| `ledger_name` | str | as it appears in the TB |
| `group` | str | Schedule III primary group |
| `sub_group` | str | optional, may be null |
| `fy` | str | `"FY22"`, `"FY23"`, `"FY24"` — sortable |
| `opening_dr` | float | ≥ 0 |
| `opening_cr` | float | ≥ 0 |
| `turnover_dr` | float | ≥ 0, period debit total |
| `turnover_cr` | float | ≥ 0, period credit total |
| `closing_dr` | float | ≥ 0 |
| `closing_cr` | float | ≥ 0 |

Derived helper columns added by `normalise.py`:
- `closing_net` = `closing_dr` − `closing_cr` (positive = debit balance)
- `opening_net` = `opening_dr` − `opening_cr`
- `movement` = `closing_net` − `opening_net`
- `turnover_total` = `turnover_dr` + `turnover_cr`

### 4.2 `derived` (one row per financial year)

Produced by `derive.py` from `ledgers` + `group_nature.yaml`.

```
fy, revenue, other_income, cogs, gross_profit, employee_cost, other_expenses,
sga, depreciation, finance_cost, pbt, tax, pat,
receivables, inventory, cash, other_current_assets, current_assets,
gross_block, accum_depreciation, net_block, cwip, intangibles, investments,
loans_advances, total_assets,
payables, other_current_liabilities, current_liabilities,
wc_borrowings, lt_borrowings, total_liabilities,
share_capital, reserves, retained_earnings, net_worth,
cfo_indirect, ebit, ebitda, working_capital,
related_party_balance, unbilled_revenue
```

**Indirect cash flow** (`cfo_indirect`), required for FS-01, MS-01 and MS-03:

```
cfo = pat
    + depreciation
    + finance_cost
    - Δreceivables
    - Δinventory
    - Δother_current_assets
    + Δpayables
    + Δother_current_liabilities
    - tax_paid
```
Where Δ is `closing − opening` for the year, taken from the ledger opening/closing columns. **This is why opening balances are mandatory.** If the TB has no opening balances for the earliest year, `cfo_indirect` is null for that year and every rule depending on it is skipped with reason `"missing opening balances"`.

### 4.3 `params` (auditor-supplied, all optional except materiality)

```
performance_materiality : float          REQUIRED
peer_ratios             : dict           gp_margin, np_margin, asset_turnover,
                                         debt_equity, revenue_growth — each {mean, std}
related_parties         : list[str]      ledger names to treat as related
prior_adjustments       : list[dict]     {fy, description, amount}
governance_scores       : dict           15 question ids → 0/1/2
```

## 5. INGESTION

### 5.1 Excel path (`parse_excel.py`)

Accept both shapes and normalise to long:

- **Long**: one sheet, has an `FY` / `Year` / `Period` column.
- **Wide**: one row per ledger, repeating column blocks per period (Tally's comparative export). Detect by finding repeated header patterns (`Opening`, `Debit`, `Credit`, `Closing`) and melt to long.
- **Multi-sheet**: one sheet per year. Infer FY from sheet name (`FY22`, `2021-22`, `2022`).

Handle these real-world Tally export quirks:
- Merged header rows spanning 2–3 rows — find the true header by locating the row containing ≥3 of the expected column keywords.
- Group hierarchy expressed as **indentation** rather than a column — infer group from the most recent less-indented non-numeric row.
- Interspersed subtotal / "Grand Total" rows — drop rows where `ledger_name` matches `^(grand )?total|^opening|^closing` case-insensitively.
- Amounts stored as text: `"1,23,456.78 Dr"`, `"(1,234)"`, `"1,234 Cr"`. Strip commas, map trailing `Dr`/`Cr` to the correct column, treat parentheses as negative.
- Blank rows and fully-empty columns — drop.

### 5.2 PDF path (`parse_pdf.py`)

1. Try `pdfplumber.extract_table()` per page.
2. If that returns nothing usable, try `camelot.read_pdf(flavor="stream")`.
3. If a page has no extractable text at all, it is a scan — raise `ScannedPDFError` with the message: *"This PDF contains images, not text. Please supply the trial balance as Excel, or use the template in `templates/`."*

**Never score a PDF-sourced trial balance without human confirmation.** Route it to the verification screen (section 9, screen 2) with `requires_confirmation=True`.

### 5.3 Custody (`custody.py`)

On every upload, append to `runs/<run_id>/custody.json`:

```json
{
  "run_id": "uuid4",
  "timestamp_utc": "ISO8601",
  "operator": "<from settings or OS user>",
  "files": [{"filename": "...", "sha256": "...", "bytes": 123456, "format": "xlsx"}],
  "rule_versions": {"tb_rules.yaml": "<sha256 of file>", "...": "..."},
  "parameters": {"performance_materiality": 500000},
  "confirmations": [{"screen": "verify", "fy": "FY24", "confirmed_by": "...", "at": "..."}]
}
```

Append-only. Never rewrite an existing entry. This implements the chain-of-custody requirement in ICAI Ch. 6.4.1.1.

## 6. THE RULE ENGINE

### 6.1 YAML rule format

Every rule in `rules/*.yaml` follows this shape:

```yaml
- id: TB-03
  name: Suspense or control ledger carrying a year-end balance
  module: TB
  status: implemented
  requires: [trial_balance]
  min_years: 1
  branch: asset_misappropriation      # fraud tree branch
  scheme: 5                           # ICAI Ch.4.2.2 scheme number, or null
  flag: red                           # red | yellow | green
  weight: 5                           # 1-5
  confidence: 1.0                     # 0-1; 1.0 = deterministic
  source: "ICAI Ch. 6.1.1 — unreconciled subsidiary and general ledger"
  params:
    name_patterns: ["suspense", "difference", "control", "clearing", "unadjusted"]
    min_balance_pct_of_materiality: 0.25
  hypothesis: >
    Ledger {ledger_name} carried a closing balance of {closing_net} at {fy}.
    Suspense and control accounts are expected to be nil at period end;
    a residual balance is consistent with unreconciled items or with
    misappropriation temporarily parked pending write-off.
  procedure:
    - Obtain the ledger account for the full period
    - Identify the largest constituent items and their contra accounts
    - Verify the ageing of unadjusted items
    - Confirm authorisation for any subsequent write-off
```

`rule_engine.py` loads all YAML, dispatches each `id` to a function registered in a decorator registry:

```python
@rule("TB-03")
def tb_03(ledgers, derived, params, cfg):
    """Returns a DataFrame of exception rows, or empty."""
```

If a rule's `requires` or `min_years` is not satisfied, it is **skipped with a stated reason**, never silently.

### 6.2 Exception row format

Every rule returns rows with at least:

```
rule_id, fy, subject (ledger_name / group / entity), observed_value,
threshold_value, exception_value (for materiality weighting), detail (str)
```

## 7. THE 44 RULES — EXACT SPECIFICATIONS

`M` = `params.performance_materiality`. All thresholds live in each rule's `params` block in YAML; the values below are defaults.

### 7.1 Module TB — trial balance structure (14 rules)

| ID | Logic | Flag | Wt | Conf |
|---|---|---|---|---|
| **TB-01** | For each fy: `abs(Σclosing_dr − Σclosing_cr) > 1.0` | red | 5 | 1.0 |
| **TB-02** | Join `group_nature.yaml`. If expected sign is debit and `closing_net < −1`, or expected credit and `closing_net > 1` → exception. Also flag any ledger in a Cash/Bank/Inventory group with `closing_net < 0`. | red | 4 | 1.0 |
| **TB-03** | `ledger_name` matches any `name_patterns` (case-insensitive substring) AND `abs(closing_net) > 0.25 × M` | red | 5 | 1.0 |
| **TB-04** | `abs(closing_net) ≥ 0.20 × M` AND `abs(closing_net) mod 100000 == 0` | yellow | 3 | 0.8 |
| **TB-05** | `ledger_name` matches lexicon `["misc", "sundry", "other", "adjustment", "imprest", "unknown", "general", "temporary"]` AND `abs(closing_net) > 0.5 × M` | yellow | 3 | 0.7 |
| **TB-06** | Within each `group`, all pairs where `rapidfuzz.fuzz.token_set_ratio ≥ 88` OR `jellyfish.metaphone` equal. Exclude pairs differing only by a numeric suffix (`-1`, `II`). | red | 4 | 0.8 |
| **TB-07** | `turnover_total > M` AND `abs(closing_net) < 0.01 × turnover_total` | red | 4 | 0.9 |
| **TB-08** | `group` in expense or creditor groups AND `ledger_name` looks like a personal name: 2–3 alphabetic tokens, no corporate suffix from `lexicons.yaml` (`ltd`, `pvt`, `llp`, `& co`, `enterprises`, `traders`, `industries`, `services`, `corporation`, `associates`) | yellow | 3 | 0.6 |
| **TB-09** | Name-token → expected-group map in `lexicons.yaml` (e.g. token `bank` → group `Bank Accounts`; `gst`/`tds` → `Duties & Taxes`; `salary`/`wages` → `Employee Benefits`). Flag mismatch. | red | 4 | 0.7 |
| **TB-10** | `cash_on_hand_closing > max(0.02 × revenue, 500000)` | red | 4 | 0.9 |
| **TB-11** | `loans_advances_to_related / net_worth > 0.10`. Related determined by `params.related_parties`, else by group name containing `related`/`group co`/`associate`. | red | 5 | 0.9 |
| **TB-12** | Benford first-digit on `abs(closing_net)` where `> 0`. Require `n ≥ 300`; else skip with reason. Compute MAD = mean absolute deviation of observed vs expected proportions. Nigrini thresholds: `<0.006` close conformity, `0.006–0.012` acceptable, `0.012–0.015` marginal, `>0.015` non-conformity. Flag at `>0.015`. Confidence = `min(1, MAD/0.015)`. | yellow | 3 | var |
| **TB-13** | Per group with `n ≥ 5`: `RSF = largest abs(closing_net) / second-largest`. Flag `RSF > 10`. | red | 4 | 0.8 |
| **TB-14** | `turnover_dr > M` AND `turnover_cr > M` AND `abs(turnover_dr − turnover_cr) / max(turnover_dr, turnover_cr) < 0.02` AND `abs(closing_net) < 0.01 × turnover_dr` | red | 4 | 0.9 |

### 7.2 Module LG — ledger trend across years (10 rules)

All require `min_years: 3`. `fy1` = earliest, `fy3` = latest.

| ID | Logic | Flag | Wt | Conf |
|---|---|---|---|---|
| **LG-01** | Ledger absent in fy1 and fy2, present in fy3, `abs(closing_net_fy3) > M` | red | 4 | 1.0 |
| **LG-02** | Present in fy1 with `abs(closing_net) > M`, absent in fy3, and no offsetting write-off ledger movement in the same group | red | 4 | 0.8 |
| **LG-03** | `sign(closing_net)` changes between any consecutive pair AND both values `> 0.25 × M` in absolute terms | red | 4 | 0.9 |
| **LG-04** | Per group with `n ≥ 10`: `growth = closing_net_fy3 / closing_net_fy1 − 1` (skip if fy1 ≈ 0). Compute group mean and std of growth. Flag `z > 3`. | red | 4 | 0.85 |
| **LG-05** | `abs(closing_net_fy1 − closing_net_fy2) < 1` AND `abs(closing_net_fy2 − closing_net_fy3) < 1` AND `abs(closing_net) > M` | yellow | 3 | 1.0 |
| **LG-06** | For each expense group: `expense_growth_fy1→fy3 > 0.25` AND `revenue_growth_fy1→fy3 < 0.05` | red | 5 | 0.9 |
| **LG-07** | For **all three** years: `turnover_total > M` AND `abs(closing_net) < 0.01 × turnover_total` | red | 5 | 0.95 |
| **LG-08** | `closing_net` rises then falls, or falls then rises, with each leg `> 30%` of the prior value, and peak `> M` | red | 4 | 0.8 |
| **LG-09** | `misc_expense_ratio = Σ(ledgers matching TB-05 lexicon in expense groups) / total_expenses`. Flag if strictly increasing across 3 years AND `fy3 ratio > 0.05` | yellow | 3 | 0.85 |
| **LG-10** | Top-5 debtor share of total receivables strictly increasing across 3 years AND `fy3 > 0.60` | yellow | 3 | 0.85 |

| ID | Logic | Flag | Wt | Conf |
|---|---|---|---|---|

| **FS-02** | Requires `params.peer_ratios`. `revenue_growth > peer.mean + 2×peer.std` OR `np_margin > peer.mean + 2×peer.std` | **green** | 4 | 0.9 |

| **FS-05** | `inventory_growth > 1.5 × revenue_growth` | red | 4 | 0.9 |

### 7.4 Module MS — forensic models (4)

**These are NOT from the ICAI material. Label them "external model" everywhere they appear in the UI and README.**

#### MS-01 — Beneish M-Score

Needs two consecutive years. With 3 years you produce 2 scores; report both and the trend.

```
DSRI = (Receivables_t / Sales_t) / (Receivables_t-1 / Sales_t-1)
GMI  = GM_t-1 / GM_t                    where GM = (Sales - COGS)/Sales
AQI  = (1 - (CA + NetBlock + Investments)/TA)_t
       / (1 - (CA + NetBlock + Investments)/TA)_t-1
SGI  = Sales_t / Sales_t-1
DEPI = DepRate_t-1 / DepRate_t          where DepRate = Dep/(Dep + NetBlock)
SGAI = (SGA_t / Sales_t) / (SGA_t-1 / Sales_t-1)
LVGI = Lev_t / Lev_t-1                  where Lev = (CL + LTBorrowings)/TA
TATA = (PBT - CFO) / TA

M = -4.84 + 0.920*DSRI + 0.528*GMI + 0.404*AQI + 0.892*SGI
         + 0.115*DEPI - 0.172*SGAI + 4.679*TATA - 0.327*LVGI
```
Flag when `M > -1.78`. **Always report the eight component indices** — the index that drove the score is the audit lead, not the headline number. If SGA cannot be separated from other expenses, set `SGAI = 1.0` and record `"SGAI unavailable — SG&A not separable"` in the output.

Flag: red · Weight 5 · Confidence `min(1, (M + 1.78)/2)` clipped to [0,1]

#### MS-02 — Altman Z″-Score (private / non-manufacturing variant)

```
X1 = working_capital / total_assets
X2 = retained_earnings / total_assets
X3 = ebit / total_assets
X4 = net_worth / total_liabilities

Z" = 6.56*X1 + 3.26*X2 + 6.72*X3 + 1.05*X4
```
Zones: `> 2.6` safe · `1.1 – 2.6` grey · `< 1.1` distress. Flag in the distress zone.

**In the UI, state explicitly: this measures financial distress, not fraud. It is included because distress is the *pressure* leg of the fraud triangle.**

Flag: yellow · Weight 3 · Confidence 0.9

#### MS-03 — Sloan accrual ratio

```
accrual_ratio = (pat - cfo_indirect) / ((total_assets_t + total_assets_t-1)/2)
```
Flag `> 0.10`. Flag: red · Weight 4 · Confidence 0.9

#### MS-04 — Piotroski F-Score

Nine binary signals, 1 point each:

*Profitability* — ROA > 0 · CFO > 0 · ΔROA > 0 · CFO > PAT
*Leverage & liquidity* — Δ(LT debt/TA) < 0 · Δcurrent ratio > 0 · no increase in share capital
*Efficiency* — Δgross margin > 0 · Δasset turnover > 0

Flag when `F ≤ 3` **and** revenue growth `> 0.15` — weak fundamentals alongside strong reported growth is the interesting combination. Flag: yellow · Weight 3 · Confidence 0.8

### 7.5 Statistical helpers (`statistical.py`)

Also expose an **unsupervised outlier pass** used as a ranking input, not a rule:

Feature vector per ledger: `[log1p(abs(closing_net_fy3)), growth_fy1_fy3, group_relative_size, turnover_to_balance_ratio, volatility_across_3y, years_present]`

Run `IsolationForest(contamination=0.02, random_state=42)` and `LocalOutlierFactor(n_neighbors=20)`. Require `n ≥ 100` ledgers. Output an `ml_outlier_score` per ledger in [0,1]; add it to the ranking as a tiebreaker only — **it must never create a flag on its own.** State the contamination parameter in the report.

## 9. THE USER INTERFACE

Five screens, linear, `st.session_state` driven. A sidebar shows progress. The auditor should never wonder what to do next.

### Screen 1 — Engagement setup
- Client name, financial years covered, operator name
- **Performance materiality** (required, numeric)
- Optional: peer ratios (5 numeric pairs), related-party ledger names (textarea, one per line), prior-year audit adjustments
- **Predication note** — a required free-text field: *"State the circumstances giving rise to this review."* Written to the custody log. Nothing runs until it is filled.
- Continue button disabled until materiality and predication are supplied.

### Screen 2 — Upload & verify
- `st.file_uploader(type=["xlsx","xls","pdf"], accept_multiple_files=True)`
- After parse, show per financial year: ledger count, Σdebits, Σcredits, difference, and a ✓/✗ on the Dr = Cr check
- Show the parsed table, editable via `st.data_editor`, so the auditor can correct extraction errors
- **PDF-sourced data carries a mandatory confirmation checkbox**: *"I have verified the extracted figures against the source document."* Log the confirmation to custody.
- **THE GATE**: count distinct financial years. If `< 3`, disable Run and display:
  > **Found {n} year(s). This engine requires 3.**
  > {44 − available} of 44 rules would be unavailable. Upload a third year to continue.
- Show the coverage panel: *"{x} of 44 rules will run. {y} skipped — {reasons}."*

### Screen 3 — Governance questionnaire
15 questions from ICAI Ch. 6.1.3, each scored 0 (no) / 1 (partly) / 2 (yes):

1. Does management commit to aggressive or unrealistic forecasts to lenders or analysts?
2. Is there any blurring between promoters' personal and business transactions?
3. Is a significant part of management compensation tied to reported results?
4. Are there disputes among shareholders in this closely held entity?
5. Is the organisational structure complex or unstable relative to the entity's size?
6. Has there been high turnover in accounting, internal audit or IT staff?
7. Is the relationship with the current or previous statutory auditor strained?
8. Has management failed to remediate known control deficiencies on time?
9. Is there a known history of alleged regulatory or securities-law violations?
10. Is there excessive management interest in the share price or earnings trend?
11. Is the entity highly vulnerable to rapid technological or market change?
12. Is the entity under pressure from declining margins or market saturation?
13. Is growth or profitability unusual relative to industry peers?
14. Does the entity dominate its market enough to dictate non-arm's-length terms?
15. Is there significant pressure from a pending transaction or contract award?

Skippable, but if skipped the governance component of the score is recorded as "not assessed" rather than zero.

### Screen 4 — Findings
- **Entity score** with red / yellow / green bucket, large and unambiguous
- A separate **green-flag panel** — "too good to be true" indicators, never netted against the red score
- Ranked tables, three tabs: by ledger · by group · by year
- Per-flag expander: rule id, name, ICAI source, exception rows, observed vs threshold, fraud-tree branch, ICAI scheme number, hypothesis text, suggested procedure
- Three-year small-multiple sparklines for each flagged ledger
- Filter by flag colour and by module
- A persistent banner: **"Indicators are not evidence. This report establishes predication for further examination; it does not conclude that fraud has occurred."**

### Screen 5 — Export
- **Excel working paper** — sheets: `Summary`, `Exceptions_TB`, `Exceptions_LG`, `Exceptions_FS`, `Models`, `Derived_Statements`, `Hypothesis_Register` (with empty Proved / Disproved / Not Proved columns), `Coverage`, `Custody_Log`
- **Evidence Requisition List** (PDF) — a client-addressed document listing each record to obtain and, for each, the specific finding that motivates it. Example line: *"Day Book, FY24 — in connection with a closing balance of ₹18.4L in Suspense A/c (TB-03) and three ledgers squaring to nil at each year end (LG-07)."* Generate this from the flags that actually fired, using each not-implemented method's `unlocked_by` field.
- Download the custody log as JSON

## 10. SCORING (`scoring.py`)

```python
flag_score = weight × confidence × materiality_factor
materiality_factor = min(1.0, exception_value / performance_materiality)
# when a rule has no monetary exception_value, materiality_factor = 0.5

entity_score = Σ flag_score  for all red and yellow flags
green_score  = Σ flag_score  for all green flags     # reported separately, NEVER netted

if governance_scores provided:
    governance_component = (Σ governance_scores / 30) × 0.25 × entity_score_pre
    entity_score = entity_score_pre × 0.75 + governance_component

buckets:
    entity_score >= 45  → RED     "Extend audit procedures; consider a forensic engagement"
    18 <= score < 45    → YELLOW  "Design or strengthen preventive controls"
    score < 18          → GREEN   "No further work indicated; document the conclusion"
```

Roll-ups: by ledger (sum of flags touching that ledger), by group, by financial year.

Ranking within a bucket: `flag_score` descending, with `ml_outlier_score` as tiebreaker only.
