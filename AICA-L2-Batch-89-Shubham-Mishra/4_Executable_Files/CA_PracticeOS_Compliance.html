How DSC / Digital Signature is Embedded

1. Final PDF is generated → 2. cryptographic hash/ByteRange is created → 3. signer signs using a DSC token or approved eSign service → 4. the signature object and signing certificate are embedded in the PDF → 5. the recipient can validate signer, certificate chain, timestamp and whether the PDF changed after signing.

CA PracticeOS should never store the DSC private key. For production, use an approved local signing bridge/DSC component or an appropriate eSign API, with the signing operation occurring under the signer's control.

✍ Digital Signature / eSign Centre

For production, use a CCA-compliant DSC/eSign provider or approved signing component. The application should not collect or store a user's DSC private key. This prototype records signing metadata and document hashes only.

✍ Option B — CCA eSign API Integration

Production design: CA PracticeOS sends the document hash to an approved eSign service through a secure backend connector. The browser never stores the signer's private key, DSC PIN or long-lived API secret. The current edition provides the configuration, signing-request and callback workflow; a server-side connector is required to make live API calls.
Recommended production flow: Final PDF → SHA-256 hash → secure backend → CCA-empanelled ESP → signer authentication/consent → eSign → signed PDF/status callback → CA PracticeOS → signed-document vault + audit trail.

Zoho Integration

The production version can connect Zoho products through OAuth/API credentials with least-privilege scopes. Keep tokens server-side in the secure backend, not inside the HTML file.

📊 Tally Connector

How this works: this connects directly from your browser to Tally Prime's own built-in XML/HTTP gateway on your local machine — no separate server or install needed for this L1 connector. In Tally Prime: F1 → Settings → Connectivity → Client/Server configuration → set "TallyPrime acts as: Server", Port 9000, then open the company you want to connect to. This only works when Tally Prime is running on the same machine or local network as this browser — it cannot reach a cloud-hosted copy of this app, and some browsers may block the request as cross-origin (CORS); if Test Connection keeps failing after checking the above, that is the likely reason.
