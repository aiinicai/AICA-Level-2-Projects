PROJECT NAME
------------
FAMILY INVESTMENT MATRIX

CURRENT SUBMISSION VERSION
--------------------------
V7

PURPOSE
-------
Create a secure, local, low-cost family investment consolidation and tracking
application using Python and Streamlit.

The system must combine investments belonging to multiple family members,
across multiple brokers/platforms, into one consolidated dashboard while
retaining a complete transaction ledger and member-wise/broker-wise drill-down.

The system is a portfolio tracker and valuation/research dashboard. It should
not place trading orders unless a future version explicitly introduces a
separate, reviewed trading subsystem.

====================================================================
HOLDINGS ENGINE
====================================================================

The transaction ledger is the source of truth.

BUY / SIP
- increase quantity
- increase invested cost including supported charges

SELL
- calculate average cost
- remove proportionate cost
- reduce quantity
- calculate realised result

DIVIDEND
- record dividend income

BONUS / SPLIT
- adjust quantity according to implemented transaction rules

Open holdings calculate:
- net quantity
- invested amount
- average cost
- realised gain
- dividend income

Valuation layer adds:
- current price
- current value
- unrealised gain
- unrealised gain percentage

STARTUP RECTIFICATION
Problem:
Ordinary Python execution caused Streamlit runtime issues and onboarding prompt.

Solution:

- Streamlit-runtime detection
- relaunch using python -m streamlit run
- first-run Streamlit configuration
- SQLite WAL and timeout

V2
Problem:
StreamlitValueAssignmentNotAllowedError due to widget/form/session-state key collision.

Solution:
Separated form/widget keys from session state, including must_change_password.

V3
Problem:
Plotly wide-form mixed data-type error.

Solution:
- numeric coercion
- long-form chart dataframe
- safer chart helper

V4
Problems:
- poor dark-theme visibility
- manual amount arithmetic
- unreliable price fallback

Solutions:
- controlled light CSS
- explicit Plotly styling
- automatic Quantity x Price
- improved market-price candidate/fallback logic

V5
Problem:
Pandas merge failed because identifiers were float64 on one side and strings
on the other.

Solution:
Canonical identifier normalization:
- 125497.0 -> 125497
- reliance -> RELIANCE
- NaN/None -> blank
and normalize both holdings and price-cache keys before merge.

V7 PRICE PROVIDER ARCHITECTURE
====================================================================

Standard order:

HDFC
  ->
ICICI
  ->
ZERODHA
  ->
UPSTOX
  ->
YAHOO

Manual override remains available when all automatic methods fail.

If the user selects a preferred provider in Settings, attempt it first, then
continue through the remaining standard providers.

For mutual funds, use the mutual-fund NAV path rather than equity LTP logic.

Important:
Provider authentication rules and tokens can change. Never hard-code secrets
into the distributable source. Keep credentials in session/environment/secure
storage.

====================================================================
SECURITY PRINCIPLES
====================================================================

- local storage by default
- password hashes, not plaintext passwords
- broker/API secrets should not be embedded in source
- API credentials should be session/environment based
- regular database backups
- no order placement in V7
- avoid public internet exposure without deployment hardening
- review provider terms before redistribution of market data
