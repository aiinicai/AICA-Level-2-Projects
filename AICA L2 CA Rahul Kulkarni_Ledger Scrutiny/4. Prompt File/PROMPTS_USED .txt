SECTION 1 - SYSTEM PROMPT / RUN-TIME PROMPTS
---------------------------------------------------------------------
The scrutiny tool does NOT call any chatbot or large language model while it
runs, so it has no system prompt and sends no prompts at run time.
The AI used inside the tool is:
  - Isolation Forest (scikit-learn), an unsupervised machine-learning model
    that scores how unusual each ledger entry is, and
  - Benford's Law first-digit analysis (statistical fraud test).
Both run locally on the user's computer. Generative AI (Claude) was used only
to BUILD the tool, through the prompts listed in Section 2.

Act as an expert Python developer and a Chartered Accountant experienced in
statutory and tax audit in India.

Build a Python web app called "AI Ledger Scrutiny for Tally" that pulls
accounting data directly from Tally and performs ledger scrutiny as per audit
and Income-tax rules, using AI to flag unusual entries.

1. DATA INPUT
   a) Live from Tally's XML server (http://localhost:9000) by HTTP POST: list
      of companies, groups, ledgers with opening balances, and all vouchers
      with ledger entries for a chosen company and period. Handle
      invoice-mode vouchers, cancelled/optional vouchers and invalid XML
      characters.
   b) Upload of a Day Book XML exported from Tally (UTF-8 or UTF-16).
   c) Built-in demo data with deliberate errors.

2. AUDIT RULES (each exception: rule, section, severity, date, voucher,
   ledger, party, amount, remark)
   R01 Cash payment > Rs 10,000 to a person in a day incl. split payments - Sec 40A(3)
   R02 Cash receipt >= Rs 2,00,000 from a person in a day - Sec 269ST
   R03 Loan/deposit accepted or repaid in cash >= Rs 20,000 - Sec 269SS/269T
   R04 Negative cash balance on any day
   R05 Sunday / holiday entries
   R06 Round-sum amounts
   R07 Possible duplicate entries; duplicate voucher numbers
   R08 Missing or weak narration
   R09 TDS not deducted - 194C, 194J, 194I, 194H (single and aggregate limits)
   R10 Possibly disallowable expenses - Sec 37(1), 40(a)(ii), 43B
   R11 Cash/Bank in Journal vouchers
   R12 Material entries above materiality
   R13 Entries outside period / future-dated / undated
   R14 Suspense account entries
   R15 Debtors with credit balance / creditors with debit balance
   R16 Amount far above that ledger's normal level (z-score)
   Keep all limits in config.py and editable on screen.

3. AI AND ANALYTICS
   - Isolation Forest on: log amount, weekday, day of month, ledger rarity,
     z-score within ledger, round flag, narration length, voucher type.
     Flag the top ~2% with a plain-English reason for each.
   - Benford's Law first-digit test with MAD and Nigrini conformity levels.

4. USER INTERFACE (Streamlit): sidebar for data source, period, Tally
   host/port, test connection, company, thresholds and Run button. Main
   screen: key numbers and tabs for Summary, Exceptions, AI anomalies,
   Benford, Cash book and Ledger viewer.

5. OUTPUT: one-click Excel audit working paper (summary, colour-coded
   exceptions, one sheet per High-risk rule, Benford, AI anomalies,
   Prepared by / Reviewed by), plus a CSV.

6. DELIVERABLES: app.py, tally_connector.py, scrutiny_engine.py, config.py,
   report.py, demo_data.py, requirements.txt, README.md, a Windows .bat
   launcher, and the pip install command in one line.

7. CONSTRAINTS: runs fully on the local computer; simple commented code a CA
   can understand; tested on demo data before delivery.
